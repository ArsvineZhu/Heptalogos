# Spec Authoring Contract

This scope contains exact current implementation contracts.

- Keep Specs current, self-contained, semantically dense, and understandable
  without conversation history.
- Future conceptual design remains in docs/architecture or project/roadmap.
  Specs do not authorize implementation.
- Uppercase BCP 14 keywords are normative only when uppercase. IDs are
  traceability/search anchors, never substitutes for the semantic sentence.
- Give each current fact one canonical owner. Provider decisions, rationale,
  evidence, sequencing, and history remain in their own planes.
- Use only headings needed by the contract. Do not impose a universal document
  template or prose-density rule.
- PRE_PRODUCTION removal rewrites current shape and deletes obsolete aliases or
  tombstone Specs unless project/governance declares an obligation.
