# Coding-Agent Harness Evaluation

Evaluate a Skill or Harness rule by inspecting a realistic trigger and a
nearby non-trigger. Ask:

- Does it address a real recurring Heptalogos failure?
- Is the behavior project-specific rather than generic advice or a mature
  tool's responsibility?
- Does it reduce executor discretion at a meaningful boundary rather than add
  ceremony?
- Can the rule or Skill be deleted without losing a current capability?
- Does structural validation prove only structure, with behavioral execution
  reported as NOT_RUN when no independent runner exists?

Inspect what the Agent read, which owner/provider it checked, what it changed,
which overreach it avoided, and whether it stopped at the Plan's boundary.
Do not maintain a simulated scenario catalog, evaluation registry, or permanent
behavioral PASS/NOT_RUN ledger.
